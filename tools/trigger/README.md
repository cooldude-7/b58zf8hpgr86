# tools/trigger

Turns a scope or logic-analyser capture of the crank and cam sensors into
a decoder configuration.

```
python -m tools.trigger fit capture.csv
python -m tools.trigger emit capture.csv --gap-to-tdc 114.0 \
    --cam cam_in:181.0:-8:70 --cam cam_ex:181.0:-60:8 \
    --out fw/src/decoder_cal.c
```

`fit` reads a capture and tells you what is in it. `emit` writes the C.

## Why this exists

`decoder_config_b48()` ships numbers that are guesses, and the firmware
says so on its face. This is what replaces them — and more importantly,
it is what makes the scope session a procedure with a defined output
instead of an afternoon of squinting at a waveform.

## What it derives, and what it refuses to

**Derived from the signals:** crank tooth count, how many teeth are
missing, where the gaps fall, the speed range of the capture, per-tooth
timing jitter, and for each cam the number of features and the spacings
between them.

**Not derived, and not guessed:** `gap_to_tdc_deg`, and where each cam
pattern sits in the 720° cycle. Those are statements about where the
pistons are, and a crank sensor cannot see pistons. The tool takes them
as arguments and [PROCEDURE.md](PROCEDURE.md) explains how to measure
them — including why the obvious trick of having the tool work out TDC
from a piston-stop capture does not survive contact with reality.

## The one idea worth understanding

Everything here works on **spacings**, never absolute angles, because a
cam phaser translates the whole pattern rigidly: every feature moves and
no gap between features does. That is the same property the firmware
decoder is built on, and it is why this can read a capture taken on a
running engine with the phasers wherever they happened to be.

If the cam was *moving* during the capture, the fit detects it — each
cycle measures short or long by however far the cam travelled — scales
the spacings back onto a 720° cycle, and tells you the implied slew rate.
For the cleanest geometry, capture with the phasers parked: crank the
engine with no oil pressure.

## Honesty about the tests

The test suite runs against synthetic captures with known ground truth,
because no real B48 capture exists yet. That catches the failures that
matter here — a wheel that isn't 60-2, an accelerating engine, a moving
phaser, timing jitter, dropped edges — but synthetic data is generated by
the same understanding that wrote the fit, so it cannot catch a shared
misunderstanding. The first real capture is worth more than all of it.

The tool tells you when a capture is *self-consistent*. It cannot tell
you it is *right*. A capture taken with a marginal trigger level is
perfectly self-consistent and wrong.
